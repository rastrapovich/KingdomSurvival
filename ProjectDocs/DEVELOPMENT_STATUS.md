# Kingdom Survival — Development Status

Последнее обновление: 2026-08-31

> Технический журнал фактически реализованного состояния Unity-проекта. Он не заменяет канонический дизайн-документ и не повышает прототипные решения до статуса канона.

## 1. Текущий этап

**Этап: техническая стабилизация оболочки, армии и схематической карты экспедиций.**

Основная рабочая схема прототипа сохраняется:

- слева находятся `KINGDOM SURVIVAL`, `КОРОЛЕВСКИЕ ДОНЕСЕНИЯ` и постоянная плашка `КОМАНДИР`;
- снизу остаются `Столица / Армия / Экспедиция`;
- ресурсы и `ХОД` находятся справа снизу;
- `DEBUG` остаётся сверху справа;
- постоянный `ГАРНИЗОН КОМАНДИРА` виден во всех режимах;
- `ГАРНИЗОН СТОЛИЦЫ` отображается на экране `Армия`;
- маленькая кнопка `ЭКСПЕДИЦИЯ` у командира открывает быстрый список;
- основная нижняя кнопка `Экспедиция` открывает большой экран с картой окрестностей;
- три скрытые локации случайно распределяются между Западной, Северной и Восточной областями новой партии;
- маршрут строится автоматически, а маркер отряда показывает фактическое продвижение и возвращение.

## 2. Что стабилизировано

### Приказ экспедиции и состояние командира

При выборе локации создаётся отменяемый приказ на текущий день, но фактическое состояние командира до `ХОД` остаётся `В ЗАМКЕ`.

Перед расчётом завершённого дня командир переводится в `В ПУТИ`, после чего `DayResolver` продвигает поход ровно на один день.

Это убирает прежнее расхождение, когда интерфейс показывал `В ЗАМКЕ`, а runtime-состояние уже было `TravellingToLocation`.

### Обновление интерфейса без пересборки гарнизонов

Отправка, отмена, drag-and-drop и изменение походных запасов больше не требуют полного уничтожения и повторного создания карточек бойцов.

Существующие карточки:

- сохраняются в UI;
- переносятся между контейнерами гарнизонов;
- блокируются на время активной экспедиции;
- сохраняют компактный вид с одним типом бойца внутри изображения.

Полная пересборка может происходить при общем `RefreshInterface()` старых систем, но статическая USS-компоновка больше не показывает старый крупный формат карточек.

### Королевские донесения

`reportHistory` по-прежнему хранится в хронологическом порядке для логики игры.

Отображение синхронизируется событийно:

- новые донесения показываются сверху;
- прошлые уходят вниз;
- старый постоянный опрос списка и hash-проверка каждые 100 мс удалены;
- после изменения текста выполняется одно отложенное выравнивание прокрутки наверх.

### Compile hotfix UI Toolkit

После первого запуска стабилизированной версии Unity 6 обнаружил семь ошибок `CS0029` в `PrototypeUIController.StableUI.cs`.

Причина: прямое присваивание `UnityEngine.Color32` свойствам UI Toolkit типа `StyleColor` требует двух последовательных неявных преобразований (`Color32 -> Color -> StyleColor`), что C# не разрешает.

Исправлено без нового compatibility-слоя:

- все семь значений цвета drag-and-drop ghost явно преобразуются в `UnityEngine.Color`;
- `ExpeditionViews` уже использует helper, возвращающий `Color`, поэтому аналогичной ошибки там нет;
- `JourneySummary` использует `Color` напрямую;
- `Debug` и основной `PrototypeUIController.cs` прямых `Color32`-присваиваний не содержат.

Hotfix-коммит: `eaa2194` (`Fix UI Toolkit color compile errors`).

## 3. Статическая структура UI

Главная геометрия перенесена в `Prototype_Main.uxml` и `Prototype_Shell.uss`.

В UXML теперь сразу существуют:

- постоянная карточка командира;
- статус и цель командира;
- четыре кнопки мини-карточки;
- постоянный гарнизон командира;
- статический блок `СВОДКА ПОХОДА`;
- статический `ГАРНИЗОН СТОЛИЦЫ`;
- карта большого экрана экспедиций с тремя областями, маршрутами и маркером армии;
- debug-host.

C# больше не должен каждые 100–250 мс переставлять эти элементы и исправлять их размеры.

## 4. Runtime-архитектура

Вместо цепочки отдельных layout-patch скриптов используется один `PrototypeUIController.StableUI.cs`.

Он выполняет одно отложенное подключение после загрузки сцены, затем работает по событиям пользователя и игрового состояния.

Удалены как отдельные runtime-патчи:

- `PrototypeUIController.ShellLayout.cs`;
- `PrototypeUIController.ArmyLayout.cs`;
- `PrototypeUIController.ArmyBottomPolish.cs`;
- `PrototypeUIController.PersistentCommanderShell.cs`;
- `PrototypeUIController.PersistentCommanderShellVisibilityFix.cs`;
- `PrototypeUIController.UnityObjectCompat.cs`.

`FindFirstObjectByType` больше не нужен: единственный инициализатор использует прямой актуальный вызов `UnityEngine.Object.FindAnyObjectByType<PrototypeUIController>()`.

## 5. Армия

Сохраняется:

- перенос бойцов только drag-and-drop;
- обычный клик по карточке ничего не делает;
- отпускание вне двух гарнизонов отменяет перенос;
- `ГАРНИЗОН КОМАНДИРА` постоянный;
- `ГАРНИЗОН СТОЛИЦЫ` расположен непосредственно над ним на экране `Армия`;
- внутренние `ScrollView` гарнизонов отсутствуют;
- на плашках гарнизонов видны только их названия;
- карточка бойца показывает только его тип;
- изменение золота/снабжения отряда не пересобирает гарнизоны.

## 6. Экспедиции

Сохраняются два режима:

**Быстрый список**
- открывается кнопкой `ЭКСПЕДИЦИЯ` в мини-карточке командира;
- не закрывает открытый основной экран;
- до обнаружения показывает область, расстояние и неизвестную угрозу, не раскрывая название локации;
- клик по области или изображению отдаёт приказ;
- повторный клик по выбранной цели до `ХОД` отменяет приказ.

**Большой экран**
- открывается нижней кнопкой `Экспедиция`;
- занимает всю свободную рабочую область;
- содержит схематическую карту с тремя фиксированными художественными областями;
- содержание областей случайно распределяется один раз при создании партии и хранится в состоянии мира;
- неизвестная локация раскрывается только после прибытия отряда;
- цель выбирается маркером карты, а отправка подтверждается отдельной кнопкой;
- столица на карте отменяет приказ до `ХОД` либо приказывает возвращаться после начала похода;
- маршрут строится автоматически, маркер армии перемещается по завершённым дням и корректно разворачивается с текущей точки;
- `Исследовать` и `Приказать возвращаться` сохраняются.

Фиксированную вместимость быстрого списка пока не меняли — решение о большем количестве найденных локаций отложено.

## 7. Сводка похода

`PrototypeUIController.JourneySummary.cs` больше не использует `Update()` для постоянного опроса состояния.

Сводка обновляется после игровых действий:

- завершения дня;
- отправки/отмены;
- решений экспедиции;
- изменений, которые вызывают стабильное обновление UI.

Фоновые походные происшествия по-прежнему переносятся в локальную сводку и добавляют художественные подробности в соответствующее королевское донесение.

## 8. Канон

Активный канон — `KINGDOM_SURVIVAL_GAME_CONCEPT_CANON_RU_v1_4.docx`.

Версия 1.4 фиксирует возврат схематической карты окрестностей: выбор одной из трёх областей, контролируемое случайное размещение локаций, автоматический маршрут и визуальное движение одной армии без свободного прокладывания пути.

Отдельные экраны `Армия / Экспедиция`, постоянная карточка командира, постоянный гарнизон командира и быстрый список экспедиций остаются прототипными UI-решениями до отдельной команды `утверждаем`, `фиксируем` или `добавь в канон`.
