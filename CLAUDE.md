# Kingdom Survival

Компактная сюжетная 2D-RPG в славянском низком/тёмном фэнтези. Unity `6000.5.10f1`, UI Toolkit. Один разработчик и один 2D-художник — каждая система должна быть реалистична для малого производства.

Язык проекта — **русский**: документация, коммиты, обсуждения и ответы пользователю пишутся по-русски.

---

## Рабочий процесс git

**Ветка: `main`.** Пользователь явно разрешил пушить прямо в `main`. Не создавай рабочие ветки и не открывай pull request'ы без отдельной просьбы — пользователь хочет получать изменения простым `git pull`.

**Коммит — по команде.** Не коммить и не пуш по собственной инициативе. Ждём слова пользователя: «закоммить», «закоммить и запушь», «коммить», «commit», «запушь». По этой команде:

1. `git status` — убедиться, что попадает только то, что относится к задаче;
2. `git add -A` и коммит с содержательным сообщением на русском (первая строка — что сделано, дальше при необходимости — почему);
3. `git push -u origin main`;
4. коротко сообщить хеш и что вошло в коммит.

Если пользователь давно не давал команду, а накопились правки — можно напомнить одной строкой, но не коммитить самому.

**Никогда:** не переписывать историю в `main` (`rebase`, `amend`, `force-push`) без явной просьбы; не коммитить в обход `.gitignore` артефакты Unity (`Library/`, `Temp/`, `Build/`, `Logs/`, `*.csproj`, `*.sln`).

## Иерархия документации

Порядок обязателен: изменение мира начинается с лора, а не с квеста.

| Документ | Отвечает за |
|---|---|
| `KINGDOM_SURVIVAL_GAME_CONCEPT_CANON_RU_v*.md` (корень) | Фундамент игры: жанр, формат, механики, границы производства. Актуальна одна версия. |
| `ProjectDocs/LORE.md` | Устройство мира: история, география, культура, верования, мифологические законы, старые договоры. |
| `ProjectDocs/NARRATIVE.md` | Нарративный канон, инструментарий письма, рабочий банк идей, конкретный сюжетный канон. |
| `ProjectDocs/BESTIARY.md` | Правила проектирования существ, их происхождение, экология, поведение. |
| `ProjectDocs/DEVELOPMENT_STATUS.md` | Технический журнал фактически реализованного. Не канон. |
| `ProjectDocs/*_ADAPTATION.md` | Разборы референсов и границы переноса. Не самостоятельные центры канона. |

Разрешение конфликтов: механика и жанр → корневой канон; факт мира → `LORE.md`; сюжет и сцена → `NARRATIVE.md`; устройство сущности → `BESTIARY.md`.

Обязательная цепь для значимого нарратива:

`LORE → состояние мира → конфликт → инструменты NARRATIVE → квест → последствия → новое состояние мира`

**Новый закон мира, исторический факт, обычай, место или мифологическое правило нельзя утвердить молча внутри квеста.** Сначала — предложение в лор, и только после явного согласия пользователя оно становится фактом и записывается в `LORE.md`.

### Статусы записей

`[УТВЕРЖДЕНО]` / `[КАНОН]` — обязательно. `[СЮЖЕТНЫЙ КАНОН]` — утверждённый факт сюжета. `[ИНСТРУМЕНТАРИЙ]` — разрешённый приём, не чек-лист. `[РАБОЧЕЕ]` — идея, не факт мира. `[ОТКРЫТО]` — решение не принято, **не заполнять самостоятельно**. `[АРХИВ]` — отменено.

При предложении приёма обязательно указывать источник: `[KINGDOM SURVIVAL]`, `[ТАРАНТИНО]`, `[ТОБИАС]`, `[СНАЙДЕР]`, `[DISCO ELYSIUM]`, `[THE WITCHER 3]`, `[D&D / *]`, `[ERBEN / KYTICE]`, `[MICKIEWICZ / *]` и т. д. Источник объясняет метод, а не статус: хороший референс не делает идею каноном.

## Что уже утверждено по сюжету

- Центральный вопрос кампании: **«Что ты готов отдать, чтобы у твоего дома было будущее?»**
- Завязка **«Дом на чужой воде»**: паводок ломает плотину → игрок выбирает старый дорогой или новый рациональный ремонт → выбор определяет первые симптомы → расследование → первый выход дальше привычных маршрутов → Дом, считавший себя самодостаточным, стоит на водной системе, созданной совместно с чужими людьми.
- Канонический квест **«Полдень»**: сверхъестественное проявление реально, но ребёнка убивает не оно — мать в панике.
- Состав экспедиции и боя: **1 командир + 0–4 бойца** (от 1 до 5 участников). Герой может уйти один. Прототип пока требует ровно 4 — известное расхождение.

Не утверждены: личность героя, антагонист, большая тайна, первый регион, финал. Не придумывать их молча.

## Код

- `Assets/_Project/Scripts/Core` — кампания, карта, время, экспедиции, строительство.
- `Assets/_Project/BattlefieldDatabase`, `DialogueDatabase`, `UILayout` — отдельные модули с `Runtime/`, `Editor/`, `Resources/`; не тянуть Unity-зависимости в `KingdomSurvival.Core`.
- `Assets/_Project/Tests/EditMode` — EditMode-тесты.
- `BattleSandbox` — единственная основа будущих боёв. Старый стратегический `BattleSystem` удалён и не восстанавливается.

Универсальная Quest/Dialogue-архитектура **не проектируется** раньше доказанного первого большого квеста — сначала контент, потом система.

В удалённой среде Unity Editor, C# compiler и Test Runner недоступны. Если изменения затрагивают код, честно писать в отчёте, что компиляция и тесты не запускались.
