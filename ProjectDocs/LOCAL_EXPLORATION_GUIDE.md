# Исследуемые места, бой на месте и внешние участники — инструкция

Статус: техническая инструкция (не канон). Канон — `KINGDOM_SURVIVAL_GAME_CONCEPT_CANON_RU_v1_53.md` §28.3, §28.9–28.10; порядок работ — `PROTOTYPE_DEVELOPMENT_PLAN.md`, поставка 12К. Пилот — Старая шахта (`FreePlayMineLocal`). Конкретные места, проходы, числа и участники — `[РАБОЧЕЕ]`, пока пользователь не скажет «утверждаем».

## 1. Как устроено

| Слой | Где | Что делает |
|---|---|---|
| Поле | База полей боя (`BattlefieldDatabaseAsset`) | Фон, кадр 16:9, сетка арены 7/8/9/10/9/8/7, **стены = отключённые гексы**, флаг «ждёт рисунка» |
| Конфигурация места | `LocalLocationDefinition` (Core); значения по умолчанию — модуль содержания (`LocalLocationCatalog.RegisterDefault`), правка — `KingdomSurvivalLocalLocations.asset` в Inspector | Входы, объекты, противники с `InstanceId`, столкновения, трудные клетки, минуты на шаг |
| Состояние места | `GameState.LocalExploration` (Core, `LocalExplorationService`) | Активный слой, позиции отряда, однократные действия, противники по `InstanceId`, применённые итоги боёв |
| Геометрия | `LocalLocationGeometry` (BattlefieldDatabase) | Проходимость = клетка арены, не стена поля и не клетка объекта; путь; клетки взаимодействия |
| Движение | `LocalPartyMover` (BattleSandbox.Runtime) | Командир по пути, спутники по его следу, без наложения; ожидание отставших |
| Экран | `LocalExplorationView` (BattleSandbox.UI) + `PrototypeUIController.LocalExploration.cs` + `local-exploration-screen` в `Prototype_Main.uxml`, `LocalExploration.uss` | Поле, фигуры (те же наборы анимаций, что в бою), подписи объектов, отряд «С вами / Свита / Ранен / В лагере», «Выйти» |
| Бой на месте | `LocalExplorationService.BuildEncounterRequest` → `BattleSandboxController.HostLocalBattle` | Тот же BattleSandbox в основной сцене, на том же поле и с теми же стенами; итог — `CampaignBattleBridge.ApplyResult` (однократно, вместе с местом) |

Время: пока отряд в месте, мировые часы стоят; шаг командира тратит `HoursPerCell` (трудная клетка — вдвое), действие объекта — `HoursPerInteraction` через `ContinuousSimulationSystem.AdvanceLocalHours`. Дорожных случайных проверок внутри места нет.

Сохранение: формат 2, новые поля добавочные. Во время боя на месте ручное сохранение запрещено с пояснением; перед боем — автосохранение. Место, которого больше нет, после загрузки возвращает отряд к входу с сообщением.

## 2. Новое исследуемое место — по шагам

1. **Поле.** В «Базе полей боя» добавить поле: ID, название, фон (или флаг «ждёт рисунка» — тогда рисуется заглушка камень/пол), теги (местность), отключить гексы-стены. Проверка базы не должна давать ошибок; поля разорванного на части быть не должно.
2. **Конфигурация.** В модуле содержания (как `FreePlay/Runtime/FreePlayMineLocal.cs`) создать `LocalLocationDefinition` и зарегистрировать её в `Register()` режима: `LocalLocationCatalog.RegisterDefault(...)`. Указать `ModeId` режима (пусто — все режимы) и `WorldLocationId` места глобальной карты. Затем добавить ту же запись в `KingdomSurvivalLocalLocations.asset` (или удалить ассет — он заведётся заново из значений по умолчанию при открытии проекта).
3. **Входы.** Клетка входа — проходимая; через неё же выходят. Выход возможен, только когда группа физически собралась.
4. **Объекты.** Ставить на клетку стены или края: объект занимает клетку, к нему подходят с соседней проходимой. Вид — `Dialogue` (сцена из Базы диалогов) или `Inspect` (короткий текст). `OnceOnly` — отработал один раз; `RequiresFlag`/`HiddenWhenFlag` — видимость по флагу истории. **Находки, у которых уже есть флаг истории, хранятся только этим флагом.**
5. **Сцены.** Сцены объектов писать в production-формате `NARRATIVE.md` §5A.17, одна реплика — один шаг (§4.10). Присутствие спутника — условие `CompanionPresent`: его видят только те, кто здесь (§4.8, канон §28.9). Свою проверку не делать перебрасываемой: `CheckNotAttempted` по тому же `CheckId`.
6. **Противники.** Каждый — отдельный `InstanceId`, тип из Базы существ, уровень, логово (клетка), столкновение. Погибшие не возрождаются; после отхода отряда выжившие возвращаются в логово с теми же ранами.
7. **Столкновение.** Зона угрозы (клетки), вступительная сцена (одна реплика), префикс ID боя, разрешён ли отход и **безопасная точка вне зоны угрозы** (иначе бой зациклится — проверка это ловит), спутник для подготовленного начала, флаг истории, который исчерпывает столкновение (например, «логово очищено»). Последствия победы пишет история места (`CampaignContent.OnBattleApplied`).
8. **Проверка.** Inspector базы мест → «Проверить места». Проверяются ID, поле, входы, объекты (можно ли подойти), диалоги, существа, клетки противников и угрозы, точка отхода, место для боя. EditMode-тест места — по образцу `FreePlayMineLocalTests`.

Места без локальной карты продолжают открываться прежним текстовым входом (Location Interaction). Место с локальной картой текстового входа не показывает.

## 3. Внешний участник (наёмник, существо-союзник)

Канон §28.10: редкое исключение, занимает одно из четырёх мест бойца, не член населения Дома; бестиарий не нанимаемый, каждое существо-союзник — отдельное авторское решение с проверкой по `BESTIARY.md` и `LORE.md`.

Технически участник — та же пара записей, что у бойца, без семьи и домашней функции:

- `FighterData` (ID, имя, `UnitTypeId`) в `GameState.Fighters`;
- `ResidentState` с тем же ID: `Membership = External`, `Origin = Mercenary` или `CreatureAlly`, `UnitTypeId`, пустой `HouseholdId`; здоровье — в этой же записи (`EnsureCombatState`), отдельного реестра HP нет;
- допуск в поселения: `SettlementAdmissionBlock` — причина отказа, которую игрок видит заранее; `SettlementAdmissionExceptionFlag` — флаг истории, снимающий запрет.

В бою существо-союзник берёт шаблон из общего каталога существ (`CampaignParticipantOrigin` не `HomePerson`); человек Дома — только из отряда. Неверный тип в бою на месте — ошибка данных, бой не начинается.

Не решено и не реализовано: цена и срок найма, конкретные наёмники и существа, договоры, обучение и награды духа, территориальные ограничения, раскрытие скрытой природы.
