# Kingdom Survival — Development Status

Последнее обновление: 2026-09-03

> Технический журнал фактически реализованного состояния Unity-проекта.
> Актуальный канон основной игры: `KINGDOM_SURVIVAL_GAME_CONCEPT_CANON_RU_v1_15.md`.

## 1. Текущий этап

Исправлена рассинхронизация между фактическим расчётом Defense и его отображением в BattleSandbox.

Причина ошибки: боевой runtime уже использовал новую формулу стойки и бонус холма, но интерфейс продолжал показывать старые значения. В карточке бойца было буквально захардкожено `+2` для стойки, а панель текущего бойца выводила только базовый `Defense` из определения существа.

Канон v1.15 не менялся. Исправление приводит UI в соответствие уже утверждённым правилам тактического прототипа.

## 2. Единый расчёт отображаемой защиты

Добавлены `SandboxDefenseSnapshot` и `SandboxDefensePresentation`.

Снимок защиты содержит:

- базовый `Defense`;
- бонус `Бронированный +2`;
- бонус холма `+2`;
- бонус защитной стойки;
- итоговую эффективную защиту.

Порядок остаётся прежним:

`Defense + Armor + Hill`, затем `Guard = max(1, floor(предыдущая сумма × 0.50))`.

Пример гвардейца на холме:

`4 Base + 2 Armor + 2 Hill = 8`, стойка даёт `floor(8 × 0.50) = +4`, итог `12`.

## 3. Исправление BattleSandbox UI

Добавлен `BattleSandboxDefenseUiRefiner`, работающий только в сцене `BattleSandbox`.

Теперь панель текущего бойца показывает реальную эффективную защиту и строку разбора, например:

`ЗАЩ 12`

`ЗАЩИТА: База 4 · Броня +2 · Холм +2 · Стойка +4`

Карточка бойца по ПКМ также получает фактическое итоговое значение вместо старого захардкоженного `Defense + 2`.

При наведении на характеристику `ЗАЩИТА` текст подсказки обновляется и сообщает актуальное правило стойки: `+50%`, округление вниз, минимум `+1`, после брони и холма.

Это устраняет визуальное впечатление, что холм не работает или стойка всегда даёт только `+2`.

## 4. Холмы

`SandboxTerrain.Difficult` в пользовательской логике считается **холмом**.

Правила:

- стоимость входа — `2` движения;
- клетка проходима;
- боец на холме получает `+2 Defense`;
- бонус действует на игрока и AI;
- бонус определяется по текущей позиции;
- при уходе с холма бонус исчезает;
- случайная генерация создаёт `6–10` холмов на бой.

ПКМ по пустому холму открывает карточку `ХОЛМ` с описанием стоимости движения и бонуса защиты. ПКМ по бойцу имеет приоритет.

## 5. Защитная стойка

Стойка одинакова для всех бойцов:

- бонус = `50%` от защиты после плоских модификаторов;
- округление вниз;
- минимум `+1`;
- отдельного `+75%` для `role.defender` нет.

Примеры:

- Defense `1` → `2`;
- Defense `3` → `4`;
- Defense `4` → `6`;
- Defense `4` + Armor `2` → `9`;
- Defense `4` + Armor `2` + Hill `2` → `12`.

## 6. Случайная местность

Сохраняется предыдущая генерация:

- `6–10` холмов;
- `3–5` непроходимых активных клеток;
- стартовые клетки бойцов свободны;
- стартовые позиции обеих сторон остаются связаны проходимым маршрутом;
- повторный бой создаёт новый случайный рисунок.

## 7. Тесты и проверка

Добавлены интеграционные проверки эффективной защиты:

- фактический `PreviewAttack` наносит меньше урона цели на холме;
- снимок защиты показывает `Base / Armor / Hill / Guard` в правильном порядке;
- для `Defense 4 + Armor 2 + Hill 2` стойка даёт `+4`, итог `12`;
- итог снимка совпадает с `SandboxCombatTagRules.GetEffectiveDefense`.

Ожидаемое структурное количество EditMode-тестов: **105**.

Unity Editor и C# Test Runner в подключённом окружении отсутствуют, поэтому фактическая компиляция и запуск тестов здесь невозможны. Выполнена статическая проверка связей Runtime/UI и тестового сценария.

## 9. Что проверить после pull

1. Дождаться компиляции Unity без ошибок.
2. Открыть карточку бойца с `Defense 3`, включить стойку и убедиться, что показывается итог `4`, а не старое `+2`.
3. Поставить бойца на холм и убедиться, что отображаемая защита сразу возрастает на `2`.
4. Проверить гвардейца на холме: `4 + 2 Armor + 2 Hill = 8`, в стойке — `12`.
5. Открыть ПКМ-карточку бойца на холме: значение `ЗАЩИТА` должно совпадать с панелью текущего бойца.
6. Увести бойца с холма: строка `Холм +2` должна исчезнуть.
7. Проверить прогноз урона по одной и той же цели на обычной клетке и на холме: на холме урон должен быть ниже при прочих равных.
8. Запустить EditMode Test Runner; ожидается **105** успешных тестов.
