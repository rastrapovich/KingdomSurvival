# Dialogue Database — technical status

Дата: 2026-09-07

## Реализовано

- Добавлен отдельный модуль `Assets/_Project/DialogueDatabase`, не смешанный с `ExpeditionDecisionSystem` и не добавляющий Unity-зависимости в `KingdomSurvival.Core`.
- Создан `DialogueDatabaseAsset` в `Resources/DialogueDatabase/KingdomSurvivalDialogues.asset`.
- Один источник данных используется для тестовых, сюжетных, побочных, случайных, бытовых и служебных разговоров; категория является метаданными, а не отдельной runtime-системой.
- Диалог хранит ID, название, категорию, производственный статус, комментарий, теги, стартовый узел и произвольное число узлов.
- Узел хранит `Node ID`, говорящего, текст и произвольное число ответов; ответ ведёт в другой узел либо завершает разговор.
- Добавлен справочник говорящих: стабильный ID, имя, подпись/роль и Sprite-портрет.
- Runtime-адаптер превращает записи базы в существующие `NarrativeDialogueDefinition / NarrativeDialogueSession`.
- `NarrativeDialogueNode` расширен необязательным `SpeakerId` без ломки старого конструктора.
- `PrototypeUIController` получил `TryOpenNarrativeDialogueById(string)`. Тестовый мельник больше не прописан репликами в C#: он загружается как `prototype_miller` из базы.
- Диалоговый UI подставляет имя, роль и портрет текущего говорящего; геометрия по-прежнему контролируется отдельным `UI Конструктором`.
- Основной прототип, `UI Конструктор` и Dialogue Database используют один и тот же диалоговый контент; игровое окно сохраняет историю реплик и выбранных ответов и прокручивает её к актуальному месту.

## Unity Editor

Меню: `Kingdom Survival → База диалогов`.

В окне доступны:

- поиск по ID, названию, тегам и говорящим;
- фильтр по категориям;
- создание, дублирование и удаление диалогов;
- редактирование метаданных, тегов и стартового узла;
- отдельная вкладка `Говорящие` с назначением портрета;
- встроенный проигрыватель веток без запуска игровой сцены;
- проверка выбранного диалога и всей базы;
- два режима структуры выбранного разговора: `Граф` и резервный точный режим `Таблица`.

## Визуальный граф диалога

Основной режим редактирования структуры — node graph.

Поддерживается:

- отдельная карточка для каждого узла с `Node ID`, говорящим, портретом, репликой и всеми ответами;
- видимые линии ветвлений между ответами и целевыми узлами;
- `START` для стартового узла и `EXIT` для завершающих ответов;
- перетаскивание узлов;
- масштабирование колёсиком и кнопками `− / +`;
- панорамирование средней кнопкой мыши либо `Alt + ЛКМ`;
- перетаскивание выходного порта ответа на другой узел для создания перехода;
- выпадающая цель каждого ответа для быстрого выбора любого существующего узла либо `EXIT`;
- автораскладка веток по глубине от стартового узла;
- сохранение положения узлов в самом `DialogueDatabaseAsset`; это только editor-метаданные и на runtime-логику не влияет;
- визуальное выделение недостижимых из `START` узлов;
- `prototype_miller` уже имеет сохранённую стартовую раскладку, поэтому после Pull граф не должен открываться стопкой из нодов в одной точке.

Старый списочный способ не удалён: режим `Таблица` остаётся для точной ручной проверки ID, переходов и редких случаев.

## Валидация

Проверяются:

- дубли и пустые ID говорящих/диалогов/узлов;
- пустые названия, реплики и ответы;
- неизвестные говорящие;
- отсутствующий стартовый узел;
- переходы в отсутствующие узлы;
- некорректный `EXIT` с переходом;
- узлы без ответов;
- недостижимые узлы;
- отсутствие любого достижимого выхода из разговора.

Циклы сами по себе не являются ошибкой, если из них существует достижимый выход.

## Тесты и граница этапа

EditMode-тесты по-прежнему проверяют загрузку дефолтной базы, валидацию и преобразование `prototype_miller` в runtime-диалог с сохранением `SpeakerId`. Дополнительно проверяется, что у всех узлов дефолтного `prototype_miller` сохранены editor-позиции графа.

На этом этапе намеренно не добавлены `Narrative State`, условия показа ответа, проверки навыков, эффекты выбора и универсальная Quest System. Визуальный граф меняет только authoring-инструмент: runtime-структура `DialogueNodeData → DialogueChoiceData → nextNodeId` остаётся прежней.

Unity Editor, C# compiler и Unity Test Runner в подключённом окружении недоступны. После Pull требуется дождаться компиляции, открыть `Kingdom Survival → База диалогов`, проверить `prototype_miller` в режиме `Граф`, перетащить один узел, сменить одну ветку, сохранить Asset, нажать `Проверить все диалоги` и пройти тот же разговор через встроенный preview и DEBUG MENU в `Prototype_Main`.
