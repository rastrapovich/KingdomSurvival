## 2. Журнал: три вкладки одного состояния

- **Дела** — как сейчас (цели главы), через общий вход `JournalProviders` (регистр провайдеров по кризису; глава 1 — первый). Хроника не пересобирает сюжет — только проекция.
- **Сведения** — открытые знания карточками: название, **что известно** (текст той реплики, которая дала знание), **откуда** (сцена и говорящий), **насколько надёжно**: *слух* / *наблюдение* / *установлено*.
- **История** — значимые события по дням и часам (§4). Сохраняется, после загрузки на месте.
- Журнал по-прежнему не ставит время на паузу; «НОВОЕ» — на новых сведениях и записях истории.

## 3. Сведения — без выдумки текста

- Текст карточки **не пишется заново**: при открытии знания берётся текст блока диалога, который его дал (эффект «знание» в базе диалогов), и название сцены/говорящий. Игрок видит ровно то, что уже прочёл, — без недоступной герою истины.
- Для знаний, которые даёт код (не диалог), — короткий рабочий текст в каталоге главы.
- **Степень уверенности** [РАБОЧЕЕ], вопрос 2:

| Знание | Уверенность |
|---|---|
| second_loaf_is_ration (второй хлеб — паёк), old_custom (старый обычай), drowned_woman_story (история утонувшей), old_road_avoided_lowland (старая дорога обходила низину) | слух |
| water_flow_is_wrong, mill_moves_at_wrong_time, cattle_avoid_old_branch, fish_pattern_changed, old_seventh_channel, old_ford, seven_tooth_object, downstream_people | наблюдение |
| old_agreement, shared_water_system, home_was_not_self_sufficient | установлено |

- Слух со временем может подтвердиться: если позже открыто связанное «установлено» — карточка слуха получает пометку «подтвердилось» (без раскрытия больше, чем знает герой).

## 4. История — только значимое

Записывается **один раз на событие** (стабильный ID), без тиков ресурсов и служебных вызовов [РАБОЧЕЕ], вопрос 3:

- паводок; выбор ремонта плотины; принятие или отказ семье Тихона; восстановление хозяйственного настила;
- выход в поход главы (кто пошёл); способ у брода; встреча с людьми ниже по течению; соглашение раскрыто; решение N14½;
- бой: исход, погибшие поимённо, тяжелораненые; гибель человека вне боя;
- возвращение домой; выбор пути героя; итог Совета.

Формат: «День 3, 21:00 — Паводок. Вода сорвала настил у мельницы». Текст — короткий, из уже случившегося.

## 5. Связь с картой

- У записи истории или сведения с известным местом (область поиска, нижнее поселение, найденное место) — кнопка «Показать на карте»: открывает карту и выделяет место.
- Слух без точного места маркера не получает («где-то ниже по течению»).

## 6. Цепь «решение → отложенное последствие → новая ситуация → решение»

Показать существующую полную цепь в Истории, связав записи [РАБОЧЕЕ], вопрос 4: **способ у брода** (N12б) → **обратный путь через брод** (без остановки или снова обход, ПР-09) → **стоянка у брода с дозором** → решение на ночь. Запись последствия ссылается на исходное решение («Потому что край укрепила Лада…»). Новых цепей в ПР-11 не добавлять.

## 7. Сохранения и проверка

- Сохраняется: история (список записей), отметки «прочитано» для сведений и истории; сведения выводятся из NarrativeState.
- EditMode: карточка знания берёт текст блока-источника; уверенность; «подтвердилось»; история — одна запись на событие, ничего служебного; порядок по времени; сохранение; «Показать на карте» только для известных мест; прохождение главы «игроком» даёт ожидаемый набор записей и сведений без повторов.
- PlayMode: журнал открывается, три вкладки, запись истории после события, время не на паузе.
- Вручную: после перерыва за минуту понятно, что происходит и куда идти.
