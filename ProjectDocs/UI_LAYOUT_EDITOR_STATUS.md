# UI Layout Editor — implementation status

Дата: 2026-09-07

## Что работает

- Добавлен отдельный `KingdomSurvival.UILayout` runtime-модуль и editor-модуль, не затрагивающие `KingdomSurvival.Core`.
- Добавлен `UILayoutDatabaseAsset` с референсным разрешением 1920×1080 и зарегистрированным экраном диалога.
- Добавлен Unity EditorWindow `Kingdom Survival → UI Конструктор`.
- В редакторе доступны выбор экрана/элемента, drag, resize за правый нижний угол, точное редактирование Rect, перемещение стрелками (1 px / 10 px с Shift), назначение Sprite/Texture2D, Cover/Contain/Stretch, scale/offset, tint, opacity, Undo, сохранение и валидация.
- Изображение сразу показывается на preview; scale/offset применяются к отдельному фоновому слою и не двигают содержимое UI-элемента.
- Диалоговый прототип подключён к `UILayoutDatabaseAsset`: затемнение, панель, портрет, имя, роль, текст и контейнер вариантов ответа получают геометрию из базы.
- Layout масштабируется от референсного 1920×1080 к фактическому размеру UI Toolkit screen.
- Добавлены EditMode-тесты загрузки и валидации базы.

## Что проверено

- Изменения изолированы от `GameState`, карты, экономики, боя и `ExpeditionDecisionSystem`.
- `KingdomSurvival.Core` по-прежнему не получает UnityEngine/UI Toolkit dependency.
- В репозитории добавлены `.meta` для новых Unity assets/scripts/assemblies.
- База содержит уникальные ID и положительные размеры элементов.

## Ограничения и ручная проверка

Подключённое окружение не содержит Unity Editor и в репозитории нет настроенного CI, поэтому C# compilation и Unity Test Runner здесь не запускались.

После Pull нужно:

1. дождаться Unity compilation и проверить Console;
2. открыть `Kingdom Survival → UI Конструктор`;
3. убедиться, что база `KingdomSurvivalUILayouts` подхватывается автоматически;
4. подвигать/масштабировать `Панель диалога` и `Портрет`, назначить тестовую текстуру и сохранить Asset;
5. запустить тестовый диалог через DEBUG MENU и проверить соответствие runtime редактору;
6. запустить EditMode tests.

## Следующий шаг

После проверки инструмента подключать остальные существующие крупные UI-блоки по одному, не превращая v1 в замену Unity UI Builder.

## Интеграция Dialogue Database / UI Конструктора / основного прототипа — 07.09.2026

### Реализовано

- исправлена причина пустого `prototype_miller`: координаты зарегистрированных UI-блоков продолжают храниться как экранные, но runtime теперь переводит Rect дочернего элемента в локальные координаты его `parentId` перед применением к реальному вложенному UI Toolkit-элементу;
- для диалогового layout закреплена иерархия `overlay → panel → speaker/role/divider/text/choices` и `overlay → portrait`, при этом ранее выставленные экранные координаты сохраняются и не требуют ручного пересчёта;
- `UI Конструктор` получает реальные данные выбранного разговора из `DialogueDatabase` и показывает имя/роль/реплику/варианты ответа из того же источника, который использует игровой runtime;
- в DEBUG-разделе основного прототипа вместо жёстко заданного `prototype_miller` добавлен выбор всех разговоров из `DialogueDatabase`, отображение ID/категории/статуса и универсальная кнопка запуска выбранного диалога;
- `NarrativeDialogueSession` хранит историю текущего разговора: реплики собеседника и выбранные ответы игрока;
- игровое окно диалога выводит историю в прокручиваемой ленте: старые реплики и ответы остаются выше, новые добавляются вниз, после изменения выполняется автопрокрутка к актуальной части;
- выход из разговора и существующая блокирующая пауза сохранены;
- добавлены EditMode-тесты истории `NarrativeDialogueSession` и перевода экранных координат UILayout в локальные координаты родителя.

### Граница изменения

- канон, `GameState`, карта, бой, экономика и универсальная quest-система не менялись;
- Dialogue Database остаётся источником контента, UI Конструктор — источником геометрии/фоновых текстур, основной прототип — местом runtime-показа;
- это интеграционный UI-этап, а не утверждение новой универсальной dialogue/quest-архитектуры поверх уже зафиксированной нарративной границы v1.26.

### Проверка и ограничения

- изменения были статически проверены по точному списку файлов и assembly-зависимостям;
- Unity Editor и CI в подключённом окружении недоступны, поэтому C# compilation и Unity Test Runner здесь не запускались;
- после Pull нужно проверить `prototype_miller`, несколько веток разговора, накопление истории и preview того же диалога в `Kingdom Survival → UI Конструктор`, затем запустить EditMode tests.

## Диалог: автопрокрутка и затухание прочитанного — 07.09.2026

### Реализовано

- после каждого перехода на новую реплику история автоматически доводится до самого низа, а не только пытается показать последний элемент через `ScrollTo`;
- автопрокрутка выполняется повторно после layout-pass UI Toolkit и принудительно ставит вертикальный scroller в `highValue`, чтобы новая реплика не оставалась частично ниже видимой области;
- в истории разговора только самая новая реплика остаётся полной яркости;
- все предыдущие реплики собеседника и уже выбранные ответы игрока получают пониженную opacity и визуально уходят в прочитанный фон;
- текущие варианты ответа не затухают до выбора;
- ручная прокрутка вверх не перетягивается обратно вниз, пока в историю не добавится новая запись.

### Граница и проверка

- Dialogue Database, граф диалогов, структура узлов, канон, `GameState`, карта, бой и экономика не менялись;
- изменение вынесено в отдельный partial-файл presentation-слоя `PrototypeUIController`, чтобы не переписывать уже работающую логику хранения истории;
- статически проверено отсутствие другого `LateUpdate` у `PrototypeUIController` и сохранение одной записи UI на одну запись `NarrativeDialogueSession.History`;
- Unity Editor и CI в подключённом окружении недоступны, поэтому фактическая C# compilation и Unity Test Runner здесь не запускались;
- после Pull вручную проверить длинную ветку разговора: новая реплика должна быть полностью видна снизу, а все старые реплики и выбранные ответы — тусклыми.
